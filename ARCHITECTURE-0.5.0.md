# CROC_PRO — архитектура и план реализации 0.5.0

## 1. Цель

0.5.0 — первая эксплуатационная фаза рефакторинга CROC_PRO для компьютерного клуба на Windows 10/11. Сохраняется существующая точка входа `launcher.vbs`, WinForms GUI и PowerShell 5.1; новые функции добавляются отдельными модулями в `tools\`.

Принцип разделения: Langame остаётся владельцем времени сессии, биллинга и продления. CyberCroc отвечает за клиентский интерфейс, товары, заказы, вызовы, сообщения, карту ПК, обслуживание и техническую автоматизацию.

## 2. Роли

- `client` — самообслуживание, каталог, заказ, вызов админа, FAQ, аккаунты/лаунчеры без админских операций.
- `admin` — главный ПК, полный интерфейс после мастер-пароля.
- `management` — задел архитектуры для будущего централизованного управления; фактическое управление флотом в 0.5.0 выполняется с админского ПК через discovery + SMB + UDP.

Мастер-пароль вводится при установке/настройке админского ПК и хранится через Windows DPAPI. В репозитории открытый пароль не хранится.

## 4. Поток заказа и вызова

1. Клиент создаёт локальную запись в `data\orders.json` / `data\calls.json`.
2. Операция атомарно добавляется в `data\queue.json`.
3. При наличии admin beacon сообщение уходит UDP broadcast на 50505.
4. Админский GUI принимает JSON и дедуплицирует по `order_id` / `call_id`.
5. Админ отвечает ACK.
6. Клиент получает ACK и удаляет соответствующую запись из `queue.json`.
7. При отсутствии сети очередь остаётся на диске и повторно отправляется после восстановления связи.

Форматы сообщений специально не содержат пароли, токены и другие секреты.

## 5. Discovery

Каждый экземпляр отправляет beacon через UDP 50505 с:

`pc_id`, `role`, `zone`, `version`, `host`, `timestamp`.

Админ строит локальный список узлов и может отправлять `message`, `block`, `unblock`, `emergency`.

Порог `EXPECTED_PCS` задаётся в config; по умолчанию 50, чтобы обслуживать два клуба 25+25.

## 6. Google Sheets

На админском ПК задаются URL/ID таблицы, range и путь к JSON service account. Клиентские ПК интернет/API не используют: они читают только `data\products-cache.json`, который админ может разослать по SMB.

Аутентификация реализована через JWT service-account assertion (RS256) и OAuth token endpoint Google; данные товаров читаются/обновляются через Sheets API v4 Values GET/UPDATE. Сервисный JSON-ключ не копируется на клиентские ПК.

Схема минимально ожидает заголовки `name`/`товар`, `price`/`цена`, `quantity`/`qty`/`остаток`; `category` и `sku` поддерживаются дополнительно.

## 7. Надёжность

- JSON записи обновляются атомарно.
- Очередь хранится на диске и не зависит от окна GUI.
- Логи ротируются по размеру 10 MB и возрасту 7 дней; архивируются ZIP при наличии `Compress-Archive`.
- Watchdog контролирует PID и heartbeat.
- При закрытии клиентского GUI окно блокируется; администратор может закрыть GUI после повторной проверки мастер-пароля.
- Установка клиента автоматически включает HKCU-политику `DisableTaskMgr`.

## 8. Обновление

В 0.5.0 основной канал — SMB `UPDATE_SHARE`; GitHub оставлен как явно включаемый режим разработки (`GITHUB_UPDATE_ENABLED=1`). `robocopy` не перезаписывает локальные `config.ini`, `accounts.json`, `data`, `runtime` и логи.

Полноценный persistent rollback после трёх неудачных стартов — следующий этап.

## 9. Безопасность

- мастер-пароль — только DPAPI;
- service-account JSON — только на admin PC;
- секреты не логируются;
- клиентская роль не получает админские страницы;
- чужие пароли Steam/Riot/Battle.net/Epic не извлекаются из профилей и не передаются в аргументах процессов.

## 10. Совместимость

Старые точки входа и утилиты сохранены. Существующие `games.txt`, `accounts.json`, SMB-пути и legacy-файлы не удаляются автоматически. Для существенных изменений `version.txt` поднят до `0.5.0`.

## 11. Вне 0.5.0

Failover 2–3 резервных админских ПК, persistent rollback, чтение баланса Langame, shift handover, feedback, бронирование, турниры, loyalty, локатор вещей и тихие часы оставлены на следующие фазы.

## 12. Проверка

В окружении разработки отсутствует Windows PowerShell 5.1 + WinForms runtime, поэтому полноценный запуск GUI и сетевой интеграционный тест на реальном клубном сегменте выполнить нельзя. Добавлен `tests\Static-Validate.ps1` для запуска на целевой Windows-машине.
